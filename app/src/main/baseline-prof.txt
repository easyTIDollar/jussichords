# 冷启动关键路径的 Baseline Profile
#
# 背景：APK 更新后 dex 变化，系统此前在后台编好的 AOT 产物（.oat/.vdex）全部失效，
# 首次启动时应用自己的代码几乎全是解释执行，热点方法才 JIT 编译，而编译本身又占 CPU
# —— 这就是「更新安装后刚打开特别卡、动画掉帧」的直接来源。等系统后台 dex2oat
# 重跑完（通常几次启动后）就恢复，属于平台机制而非本应用的 bug。
#
# 这个文件为 AGP 提供启动关键类和方法的编译提示，实际安装与 AOT 命中仍需设备验证。
# 语法：`L类名;` 是类规则，不等于整类所有方法都是热点。
# 新增方法级规则：`HSPL类名;->方法(参数)返回值`，H/S/P 分别表示热点、启动、启动后。
# 方法参数与返回值用 ** 匹配重载；值类导致的方法名后缀仅在具体方法上用 * 匹配。
#
# 两点注意：
# 1. 这里写的是**原始类名**。release/canary 都开了 R8，本应用类会被重命名，
#    AGP 8.4+ 默认按 mapping 把 profile 重写进 APK（见 gradle.properties 里的显式开关）。
# 2. 依赖自带的 profile 仍由 AGP 合并；这里补充源码调用或同版本字节码已确认的入口。
#    不写整包通配；缺少当前版本证据的内部实现规则跳过，留待 CI 生成真实 profile。
#
# 覆盖范围 = 冷启动到首帧可达的链路：Application → MainActivity → NavGraph →
# 首屏 Library（「我的」）→ 迷你播放条 / 全屏播放器 → 启动期各 Store 初始化 → 播放服务。
